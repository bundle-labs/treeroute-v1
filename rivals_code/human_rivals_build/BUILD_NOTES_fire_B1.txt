Decisions:
 G1 availability() reads ctx.products[options.product]["manifest"] itself; returns (True, "<n> files, complete") only
    when the file exists, is JSON, lists files and "complete" is True; every waiting case (missing file, UNSET_OD6
    folder, no `complete` key, complete false, unreadable JSON) returns (False, <the product's waiting_line>) EXACTLY
    (no suffix). A registry error (product not listed by the rival, no `manifest` field) refuses.
 G2 build() checks the product FIRST (before keys), so a waiting product always refuses with the waiting_line.
 G3 Manifest checks (3.2): complete True; dataset; listing == manifest files; request_id -> request -> same file;
    request_check values exactly; D3 leadtime_hour; area [N, W, S, E] with W <= E and S <= N; regions a non-empty list;
    file name <prefix><box>_<tag>.nc with prefix hist_ / seas_ by kind; the year tag must be "y0-y1" of the request
    years, or "y0" for a one-year request (the fetcher writes hist_*_y0-y1 always, seas_*_y for one year); the files
    of a box must name the same regions and area; a region named by two boxes refuses; a slim group named by no box
    refuses; the registry manifest path must be the product_root's product_manifest.json.
 G4 netCDF check: fwinx dims exactly as 3.2; the named coordinates present with the right dims and kinds (datetime /
    timedelta / int / float); any non-scalar extra coordinate on fwinx refuses (listing variables and coordinates);
    extra scalar coordinates (`surface`) and other data variables are never read. ERA5: dates exactly every calendar
    day of the request years and one time of day for all (00:00 is not required). SEAS5: starts == request year x
    month at day 1 00:00 (in file order); steps exactly 12 h + k days, k = 150..184; valid_time == time + step on every
    cell; members 0..24 by `number` value, each exactly once (26 or 51 members are fine: the rest is never read).
 G5 Two passes per box (3.8): pass 1 = layout + the valid mask from every file (AND over files of ANY over time; SEAS5
    over members 0..24 x starts x all 35 steps) + the mixed-mask count; then map_units; pass 2 = the selected points
    only (xarray vectorised isel), each file re-opened through ctx.open_product and re-checked. Each point's cells of a
    month are summed as ONE contiguous float64 row (days; SEAS5 member-major then day), so x__fwi_mean equals
    np.nanmean of the same float64 values EXACTLY (smoke: ERA5 max |diff| 0.0). The first draft (one pass, axis-0 sums
    over the whole grid) differed by 1 ulp; replaced.
 G6 Sea window (3.3): |di|, |dj| <= sea_window_steps measured in each axis's SPATIAL order (axis sorted by its value,
    longitudes wrapped). For a monotonic axis this is the file index window of the spec; for the contiguous 0-360
    prime-meridian layout (358.75..0.5) too; it stays right for a 0-360 file stored 0..360 ascending whose box crosses
    0 deg (merged box10 / per-region sahel), where a raw file-index window would skip the western neighbours (checked
    on a toy). Ties: first minimum in latitude-major file order, among ALL points (nearest) and among window points.
 G7 map_units returns i = j = -1 and dist_km NaN for an uncovered unit (plus nearest_i, nearest_j, nearest_km).
 G8 Coverage: a row is covered when x__fwi_mean is finite; product_cell and src are "" otherwise (also for MINDAYS
    failures and uncovered units); info_end = the rule value on every key (ERA5 t + offset; SEAS5 t - 5 - 1 = issue);
    target_obs_end NaN. Only the registry's stats are written (both here).
 G9 x__fwi_pct (3.6): fwi_percentile(unit, time, x, t_ref, steps_per_year, min_ref) groups by (unit, calendar month),
    leaves the row's own month out whenever t <= t_ref (subtracts it from the equal count and |R|), mid-rank, NaN when
    |R| < 10 or x NaN. Asserts: T_ref < first test time; newest reference info_end (T_ref for ERA5, T_ref - 6 for SEAS5)
    < first issue of ctx.keys("inner") at lead 0 / ctx.keys("guard") at a lead >= 1 and < first test issue; an EMPTY
    test or pick set refuses (fail loud); extra internal assert: every table row after T_ref carries newer information
    than its reference.
 G10 The audit file map_units_lead_<L>.json is also written BEFORE the uncovered-share refusal (its FIX names it).
