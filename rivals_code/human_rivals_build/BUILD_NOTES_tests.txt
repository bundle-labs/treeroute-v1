DEFECTS / SPEC FINDINGS (found by the tests; for the owner of the named file)
=====================================================================================================================
F1 SPEC 1.10 (refs.py, builder A; FIXED in code during the build). The common export stores every x__ column as
   float32, so clip(x__hist_last_1) can never equal the saved float64 base__persistence byte for byte (max |d| ~5e-7
   on the grid toy). The parity proof must read the float64 label at the T2 step (slim train y; the saved lead-0 test
   y after the lock). Pinned by test_oracles.py::test_export_history_is_float32_...; the oracle with labels
   reproduces base__persistence AND base__damped_persistence byte for byte at leads 6 and 12. refs.py now passes
   labels (all_labels) and its parity proof passes on the toy. The spec text of 1.10 should say "the label at the T2
   step", not "x__hist_last_1" (owner / Part A draft).
F2 SPEC 1.10 coral last visit (refs.py; FIXED in code). "site key = the part of the unit id before |" is coral's
   export form only; the engine's table toy uses visit row ids with the site in another package column, which neither
   units.parquet nor the export's train rows carry. refs.py now reads the package unit from the package's lead files
   (package_units) and its parity proof passes at 183 / 365. Pinned by test_oracles.py::test_table_toy_export_units_...
F3 HQ9 floor vs the engine's table toy: 73 tune / 66 guard-fit rows, below 100, so every map rival of a table toy is
   "not calibratable" (no row, disclosed). The coral-like table mechanics (forecast-only pick on the lowest covered
   lead's guard rows, score_without_net, L tiers, last visit) are therefore toy-tested with M runners; the map path
   (F2-F5 with links) is toy-tested on the grid toy only. Not a defect; a coverage limit of the toys.
F4 tool_code_sha covers rivals_human/*.py AND adapters/*.py: any builder edit while a suite runs makes every board
   refuse "the human tool code changed since init" (seen in run f03). Run the final suite on frozen code.
F5 (harmless, for builder A) human_board_lead_<L>.csv floats are written by pandas and must be read with
   float_precision="round_trip" to compare exactly (the tests do).
F6 (builders B / C, contract) every ctx.<name> an adapter calls must exist on index.AdapterCtx; test_h20 checks it by
   source scan (getattr(ctx, ...) names count as optional). Passing at the end of the build.
